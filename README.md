# S.T.A.L.K.E.R. 2 Loadout Creator

Візуальний редактор loadouts NPC у S.T.A.L.K.E.R. 2. Дозволяє налаштувати предмети, які отримує НІП при спавні, замість ручного редагування довгого CFG-файлу.

Користувач редагує списки предметів за категоріями для `Faction_Class` та їхні відносні ваги для чотирьох рангів гравця: Novice (у поточному коді — Newbie), Experienced, Veteran, Master. Можна обирати готові пресети та ділитися власними.

Фронтенд генерує CFG і завантажує його в ZIP. Бекенд `s2-loadout-creator-rest` зберігає та завантажує пресети через REST API, а також пакує CFG у PAK.

Сайт: [dev.s2-loadout-creator.cc](https://dev.s2-loadout-creator.cc/).

## Локальна розробка

Поточний стек: TypeScript для моделі/defaults, JavaScript для UI/генератора/інтеграцій, Vite, Bootstrap, JSZip і file-saver. Порівняння з базовим пресетом у UI ще не впроваджене. Перевірки виконані на Node 26.10.0; тести імпортують `.ts` напряму через вбудовану підтримку Node. Старі Node без такої підтримки для цього запуску тестів не підходять.

```sh
npm install
npm run dev
```

Команди з поточного `package.json`:

| Команда | Призначення |
| --- | --- |
| `npm run dev` | Локальний сервер розробки |
| `npm run build` | Обов'язковий typecheck, потім production-збірка Vite |
| `npm run preview` | Перегляд зібраного фронтенду |
| `npm run lint` | ESLint |
| `npm test` | Локальні контрольні приклади й відтворення відомих дефектів без REST |
| `npm run typecheck` | `tsc --noEmit`: типізовані модулі та compile-only перевірки контрактів |

Контрольні приклади, результати етапів і межі перевірок описані в [tests/README.md](tests/README.md). Тести з префіксом `KNOWN` підтверджують відтворення відомих дефектів, а не їх виправлення. Typecheck ще не охоплює legacy JS; runtime-валідація імпорту належить етапу 2. Відомі обмеження запуску з чистого checkout зафіксовані в аудиті (F18).
